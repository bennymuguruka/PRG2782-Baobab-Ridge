# AGENTS.md — Baobab Ridge Wildlife Rehabilitation Records System

## Project and authority
- Build a desktop wildlife rehabilitation records system in C# Windows Forms with Visual Studio and .NET 8.0 or newer. `PRG2782 Project 2026.pdf` is authoritative; flag unclear requirements rather than inventing rules.
- Use plain text files for persistence only. No databases or storage-related NuGet packages. Use paths that work after a fresh clone; never hard-code machine-specific paths.
- Preserve existing work. Keep changes scoped to the requested task. Before edits, inspect this file, `TASKS.md`, relevant code, workspace, current branch and Git status. Do not reset, discard, or overwrite work without explicit approval.

## Required application features
- Add animals using labelled inputs for ID, name, species, age and recovery score. Validate before saving; on failure show a field-specific explanation and focus that field. On success append one record, show its calculated status and housing, refresh the grid and clear inputs.
- View valid records at startup in a read-only `DataGridView` with columns, in order: Animal ID, Name, Species, Age, Recovery Score, Status, Housing Unit. Select whole rows on cell click, preserve file order, and refresh after changes without duplicates. If the data file is missing, create an empty file and show an empty grid.
- Update by selecting a grid row or searching an exact ID case-insensitively. Both load the same inputs. If absent, notify and change nothing. Edit mode makes ID read-only, disables Add and enables Save Changes; Clear exits edit mode. Saving validates editable fields, recalculates classification, rewrites only the selected record, then refreshes and returns to Add mode.
- Delete one selected row only. If none is selected, ask the user to select one. Confirm with Yes/No and include ID, name and an irreversible-deletion warning. No leaves data unchanged; Yes removes only that record, refreshes the grid and clears the form if it held that record.
- Generate a summary from current records, display it in labels or read-only text boxes, and write `summary.txt`. Handle no animals without crashing.

## Validation and classification
- Trim text before every Add or Update validation. ID is required, `WR-` plus exactly four digits; uppercase before checking/saving, unique on Add and immutable after saving. Name and species are required, 1–30 characters, and cannot contain `|`. Age and recovery score are required whole numbers from 0 through 100; reject decimals and text. Users do not enter status or housing.
- Keep classification in one shared method called by both Add and Update. Use these exact status/housing values: 0–19 `Critical` / `Intensive Care Unit`; 20–39 `Serious` / `High-Dependency Ward`; 40–59 `Stable` / `Recovery Ward`; 60–79 `Recovering` / `Outdoor Enclosure`; 80–100 `Release-Ready` / `Pre-Release Camp`.

## Text files
- `animals.txt` is UTF-8 beside the running executable: no header or blank lines; one record per line with seven `|`-separated fields in this order: ID, Name, Species, Age, Score, Status, Housing Unit. Include at least eight valid starter records across at least four statuses and configure `Copy to Output Directory` as `Copy if newer`. Load assessor-provided files in this format. Skip malformed lines (at minimum wrong field count, non-numeric age/score or invalid ID), then notify once with the skipped-line total. Skipped records need not survive a rewrite.
- `summary.txt` is beside the executable, created on summary generation and overwritten, never appended. Use this order and exact labels, with values after each colon: `BAOBAB RIDGE WILDLIFE REHABILITATION CENTRE`; `ANIMAL SUMMARY REPORT`; `Generated: yyyy-MM-dd HH:mm`; separator of 40 hyphens; `Total animals`; `Average age (years)`; `Average recovery score`; separator; `Animals per status`; then `Critical`, `Serious`, `Stable`, `Recovering`, `Release-Ready`. Use two-decimal averages with `.` regardless of locale and always list all five counts. With no animals, totals/counts are zero and averages are `N/A`. Do not commit this generated file.

Handle at least `IOException` and `UnauthorizedAccessException` (including missing file/folder, locked files and permission problems); show friendly messages without stack traces and keep running. Normal use, including invalid/empty input, empty data and Save/Delete without a selection, must not cause an unhandled exception.
- Include an `Animal` class or record. Comment above every method with its purpose, add inline comments for non-obvious logic, remove obsolete commented-out code, and use meaningful names.
- The application must build and run from a fresh GitHub clone with no missing files or machine-specific paths. Build and verify all five features, validation and classification boundaries, empty/missing/malformed/read-only/locked files, exact file formats and fresh-clone operation. Do not claim verification unless run; identify anything not verified.
